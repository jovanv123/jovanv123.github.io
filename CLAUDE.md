# Portfolio site — Jovan Vasić (mechatronics / robotics)

## Stack
Astro, Tailwind, MDX, astro-icon (`@iconify-json/simple-icons` for brands, `@iconify-json/tabler` for generic icons). Static output only. No new dependencies without asking.

## Content
- `portfolio.md` (repo root) is the original content source. Its front-matter holds all config and content.
- Target structure:
  - `src/data/site.yaml`: site, theme, colors, nav, profile (greeting + name + tagline + status make the hero; photo is a file in `src/assets/`), focus (kept, not rendered), featured (aria label only), projects, experience, education, skills (groups: name, `icon`, items as label or `{ label, icon? }`; icons are iconify names like `simple-icons:ros`, `tabler:cpu`), socials, footer
  - `src/content/projects/<slug>/index.mdx`: one folder per project; frontmatter from `projects.items`, body from the case-study sections
  - Project images (cover, gallery) are colocated in the project folder and referenced relatively (`./cover.jpg`). They go through the `image()` schema helper and render with `<Image>` from `astro:assets`, never `<img>` or `public/`.
  - Videos stay in `public/media/` with a same-name `.jpg` poster next to each. `media` (`media/<name>.mp4`) is the home card's hover preview and the project page hero when there are no `slides`; `slides` (videos from `public/media/` and colocated images, edited in the MDX frontmatter) is the project page media carousel. Card thumbnail (4:3 `object-cover`): the `cover`, else the first video's poster; a video without a .jpg next to it falls back to the cover as its poster.
- Project schema (zod): title, slug, context, year, result?, summary, role?, result_detail?, cover? `{ src: image(), alt }`, media?, focus? (card 4:3 crop `object-position`, e.g. `"50% 60%"`), slides[] `{ type: "video", src, poster?, title, text, speed? }` | `{ type: "image", src: image(), alt, title, text }` (default []), gallery[] `{ src: image(), alt, caption? }` (default []), stats[] `{ value, label }` (default []), stats entries with an empty value are hidden; comparison? `{ columns[], rows[] { label, values[] } }` (Results table, shown once any cell is filled), publication? `{ title, venue, year, url }` (shown once title is filled), seasons[] `{ season, result, result_label, role, text }` (default []), tags[], repo_url?, paper_url?, featured.

## Pages
- Home (single page), each section labeled in mono (`01 — Projects`) over a hairline, hairlines between sections, ~112px between sections on desktop and ~64px on mobile (`py-14` / `py-8`):
  - Hero (`#about`, white, content height: `pt-24 pb-20` desktop, `pt-12 pb-10` mobile; headline `text-hero` = clamp(2.25rem, 4.5vw, 3.75rem), tagline 1.25rem, tight gaps): left: "Hey, I'm <name>." with the name in accent, tagline, mono status line with accent dot, text links "View work →" and "CV ↓". Right: square color photo (`theme.photo_size` 280px, vertically centred with the text) from `src/assets/<profile.photo>` via `<Image>`, alt = name, 1px hairline frame, mono location label below it. Mobile: photo first. Missing photo → framed placeholder.
  - Hero background: `FieldRobot` canvas (desktop only; hidden and not run below 768px), a mini nav stack on a 3000 × 2000 mm field scaled to the hero (origin bottom-left, y up). Faint `border` grid (~48px) with mono mm ticks, running behind the content (no cutouts). The only obstacles are the `[data-nogo]` elements (text block, photo figure, readout, reset link): never mapped, painted or driven through; the lidar rays cross the no-go margin unmapped and end exactly where they meet a text line or image box (the hit). 2D lidar (72 rays/5°, 1200 mm, 10 Hz, DDA) into a log-odds Int8 grid at 25 mm whose known cells decay back to unknown over ~60 s, so exploration never stops. The map itself is invisible (free cells transparent; there are no occupied or inflated cells to paint): only rays (`text` at 6%), fading `accent` hit points, the dashed `accent` path, the goal + and the robot are drawn, all clipped to the hero. A* (octile, binary heap, preallocated typed arrays; unknown traversable at higher cost) with line-of-sight smoothing; replans on goal change or every 1 s. Obstacles are what each element shows (one box per text line and per image, not the layout box). No-go is every cell where any point would put the robot's footprint (body at any heading, detection box and its label) within 4 px of an obstacle, so no part of the robot ever touches a lidar hit; collision checks the centre against those cells; plus a 12 px planning buffer; goals and paths stay 48 px inside the hero. Pure pursuit (150 mm lookahead, clamped at bends over 30° which it drives into at ≤ 100 mm/s, v_max 400 mm/s, a_max 600 mm/s², ω_max 2 rad/s, rotate in place over 60°) at a fixed 100 Hz. Idle it explores the nearest frontier at least 600 mm away, then patrols long legs to far, alternating points; click sets the goal (accent +, snapped if unreachable); "reset map" link top-right. Robot drawn 1.5×: diff-drive body, wheels, accent heading triangle, ArUco DICT_4X4_50 id 7, dashed `aruco id=7` detection box. Plain mono readout bottom-right, fixed width, no box (x y θ v ω, goal, path, explored, replan). Paused off-screen or on a hidden tab, DPR-aware; reduced motion shows a fully explored static map with one path. Plain TS, no libraries.
  - 01 Projects (`#projects`): full-width `surface` band with every project as a card, featured first then year descending, 3 per row (stacked on mobile). Card: 4:3 frame with the poster/loop cropped to fill (`object-cover`, `object-position` from `focus`, default centre) that plays on desktop hover (cards without media are text-only, no empty frame, stretched to the row height), a mono "View case study →" chip (white on 60% black) over the media's bottom-left on hover, reserving no height; body `p-5` with tight gaps: title (1.25rem), then a footer `result · year` on one line aligned across cards (short `result`, truncated on mobile only). White fill, hairline border, accent border on hover, whole card is the link. No list rows.
  - 02 Experience: full-width rows, date | role + company | one-line points with an optional mono `tech` line (` · `-joined) below; empty ones hidden.
  - 03 Technical skills: cards 5/3/1 per row (≥1280px / tablet, 3 + 2 / mobile), equal height per row: group name, then one row per item: small logo + label in muted text. Logos are simple-icons brands, or a generic tabler glyph where a tool has none. Icons monochrome near-black, accent on card hover with the border. Hairline border, no radius, no shadow.
  - 04 Education (`EducationTimeline`, constrained to `theme.narrow_width` 720px): vertical line on the left with a square node per entry, most recent on top. Entry: mono date range in accent, degree (semibold), school, muted note. The faint dashed hairline fills with solid accent as the section scrolls (CSS `animation-timeline` view timelines; JS fallback sets `--timeline-progress` / `.is-on` in Firefox/Safari). A node fills when the line reaches it; the current entry (`end: present`) is always filled with a subtle pulse ring. Reduced motion: fully drawn, no pulse.
  - 05 Contact: large closing line (`contact.message`, "Let’s build robots."), the email as a big mailto: link, then GitHub · LinkedIn · Google Scholar · CV as text links. Anything empty is left out.
- `/projects/[slug]`: the full content width (`theme.max_width`, 1100px), `pt-12`. Header: ← Work breadcrumb, title (`text-title` = clamp(2.25rem, 4vw, 3.25rem)) and mono context with ~12px gaps on the left (3/5); Role on the right (2/5), stacked below a hairline on mobile → media (slide carousel if `slides`, else the single `media` loop in a video stage, else cover) → summary (1.25rem, 2px accent left rule, text width) → publication line (mono label, accent title link, venue · year; only if `publication.title`) → numbered sections (01 Problem …) → Seasons → Gallery → Links (only if repo/paper) → Next project row.
  - Case-study sections (`CaseStudy` wraps the rendered MDX): two-column rows inside the column (~200px: accent mono number over the heading, 1.375rem/500; right: body 1.0625rem/1.65), stacked on mobile, full-column hairline between, ~48px / 32px (desktop/mobile) above and below each rule. Lines starting with "TODO" are never rendered and sections left empty are dropped. Lists where every item is `**Name**: description` render as a row of columns (name in mono accent, description below, hairline dividers; stacked on mobile). Results starts with the `stats` row: 2.5rem accent value, mono muted label, hairline vertical dividers; then the optional `comparison` table (hairline cells, mono header row); prose below. Body links are accent.
  - Next project: hairline-bordered row, mono `Next project →` left, title right; title turns accent on hover with an arrow sliding in.
  - Media carousel (`MediaCarousel`, vanilla TS; also renders the single `media` loop, without controls): one slide (video, or image via `<Image>`) at a time on a full-width fixed-height stage (min(70vh, 600px) from md, 60vh below, constant between slides). Every video or image, landscape or portrait, is shown whole (an image is its own blurred backdrop) (contain, no crop) and centred; the hairline-framed stage is filled with a blurred, darkened copy of the active poster (`blur(24px) brightness(0.9)`). Mono `<speed> speed` chip (white on 60% black, 11px) in the video's bottom-right corner, only on slides with `speed`. `autoplay muted loop playsinline preload="metadata"`; only the active slide loads and plays. ← / → overlaid on the stage's left and right edges as 60% black squares with white arrows, accent on hover; wraparound; arrow keys when focused or in view; swipe on touch. Below the stage (~12px): one caption line (the slide's `text`, else its `title`) at text width on the left, `01 / 03` counter right (accent on hover); 150 ms crossfade, height of the tallest caption, `aria-live="polite"`; the title is the video's aria-label.
  - Diagrams (`Flowchart` in the MDX body, `src/lib/flowchart.ts`): a Mermaid `flowchart LR` subset rendered at build time to inline SVG, no dependency. 1px near-black strokes, white nodes, `==>` edges (and their nodes) are the key path in accent, Geist Mono 11px labels (long single-line labels wrap), no radius. Scales to the body column (which goes full width for it, text stays at text width), max 320px tall; natural width with horizontal scroll inside the frame on mobile.
  - Gallery: full-width images stacked vertically, hairlines between, mono caption below each. Never a grid.
  - Seasons (`SeasonCarousel`, after the MDX sections, only if `seasons`): a numbered full-column section with one text slide per season, newest first: result as a 2.5rem accent value over its mono label and the season (left, in the case-study column grid); mono role line, paragraph (right); stacked on mobile. Same ←/→ squares at 32px, on one row with the `01 / 03` counter under a hairline ~24px below the tallest paragraph (~12px padding), keys, swipe and 150 ms crossfade as the media carousel (shared `src/lib/carousel.ts`); slides share one grid cell so the height never changes.

## Design
- Reference: datameister.ai. Light lab aesthetic, text-led: white page (#FFFFFF), near-black text (#0A0A0A), muted #71717A, hairlines #E4E4E7.
- Nav: sticky, full-width solid black bar (`inverse`): name left; Projects · Experience · Education · Contact · CV right (section IDs) as white mono text links with an accent underline on hover.
- Footer: black (`inverse`) like the nav, columns About · Contact · Elsewhere (filled from profile/socials, "—" when empty), mono copyright line.
- Light only; there are no dark-mode variants.
- Tokens come from the `theme`, `colors` and `typography` blocks in site.yaml and are mapped into the Tailwind config. Never use arbitrary inline values.
- Fonts: Geist and Geist Mono. Use mono for tags, dates, metadata and the status line.
- 1px hairline rules separate sections and list items. Never use boxes.
- Use the single accent color, royal blue (#4169E1, `accent-hover` #2F55C9 for hover/active), only for hover, focus, the status dot, the hero name, the field robot (heading, detection box, goal), the education timeline (dates, line, nodes) and, on project pages, section numbers, the summary rule, stats, body links and the carousel counter on hover. On black (nav, footer) hover is an accent underline on white text.
- Light-gray `surface` (#F4F4F5) is for full-width bands (project cards). `line` (#D4D4D8) is only for the hero robot trail.
- Project card posters use `preload="none"`, play on desktop hover and reset on leave; they stay posters under `prefers-reduced-motion`.
- Banned:
  - card grids other than the project cards and the skill cards; box-shadow, gradients, glassmorphism
  - any border-radius > 0
  - emoji, colored or multicolor icons, bordered skill chips, progress bars (icons only as monochrome logos/glyphs in the skill cards)
  - centered hero, circular photo, button CTAs (text links only)
  - hover scale; the only motion is the hero robot, video loops, the scroll-drawn education timeline and the Next project arrow
  - from the structure reference (zachjordan.io): green, rounded corners, thick black borders, emoji, icon cards

## Rules
- Internal hrefs/srcs go through `resolveHref` (respects `import.meta.env.BASE_URL`). The `check-output` integration fails the build on a broken internal link/asset or any rendered "TODO"; hide unfinished content instead.
- Semantic HTML, alt text, keyboard focus states, mobile-first.
- Use `VideoLoop` (`autoplay muted loop playsinline preload="metadata"` + poster, no controls) for media, never GIFs.
- Project page videos are never cropped: `object-fit: contain` / natural aspect ratio, on the blurred-poster `.video-stage` where the frame differs. The only `object-cover` on video is the home card crop.
- Make small, commit-sized changes. Explain what changed in 2–3 lines.
